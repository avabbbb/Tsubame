# 把一段 18 分钟的日语 ASMR 做成中文同传：skill/agent 调优记录

> 2026-10-25 至 26 日，两轮完整实测。所有数字来自实际运行日志；未做的事情明确标为未做。

## 背景

目标是让 agent 按 .agents/skills/yuzuki/SKILL.md 的指引，把日语 ASMR 音声跑完「转写 → 翻译 → 中文 TTS → 按原声左右位置渲染 → 压低原声混音 → 双音轨导出」。硬约束：只有字幕句文本能出本机，且必须先脱敏；不允许伪造测试结果。

## 踩过的坑（按发现顺序）

### 1. 「每句都太长」其实是头部在说谎

首轮 TTS 全部 260 句都被判定超出字幕时隙，结果全被压到 1.5 倍速。读出的时长约 89478 s——正好是 0xFFFFFFFF 字节按 24 kHz/16 bit 换算。ffmpeg 写管道时无法回写 RIFF/data 大小，只留占位值。修复是在 shim 里按实际字节重写头部，并加三个单测。

教训：一个数字离谱到和 2 的幂次相关时，先查容器格式，不要先调算法。

### 2. 改了代码却没生效

修复后第一句仍返回错误头部。离线调用新函数却是对的——说明请求根本没进新进程。Windows 上 Python 启动器会派生子进程，terminate 只杀父进程，旧子进程继续占着端口。现在启动前按端口清理残留进程，并核对启动行。

教训：「修复没生效」时，先证明你在测的是新代码。

### 3. 偶发 502

经代理连语音服务时偶发连接超时。shim 按设计返回 502 而不是假装成功；调用端并发从 4 降到 2，加 5 次退避重试，两轮各只有 1 句需要重试。

### 4. edge-tts 首尾静音

合成音频平均带 0.165 s 前导和 0.959 s 尾部静音。不裁时 98 句超时隙，裁掉后只剩 1 句（第二轮 3 句）。这比继续加速更自然。

### 5. 混音真峰值超标

初版样本峰值上限 0.98，混音真峰值 +0.1 dBTP。上限改为 0.85（约 -1.4 dBFS）后，解码 AAC 轨实测 -1.1 dBTP。代价是响度从 -23.7 降到 -25.0 LUFS。

### 6. 尚未解决：第二轮 ASR 慢了 5.9 倍

同模型同素材，57.5 s 变 338.4 s，stderr 有 HF Hub 未认证请求警告。假设是加载时联网校验模型，但本轮没有分开计时加载与转写，所以只能写「未验证」。

## agent 层面的调优

- 把实测坑写进 SKILL.md：每条都带「症状 → 做什么」，下一个 agent 不必重新发现。
- 把临时脚本收进仓库（workers/dubber/dev_render_mix.py），参数全部由命令行传，不硬编码路径。
- 客户端代码传输会把两个星号、双下划线、「方括号接圆括号」当成 markdown 吞掉，导致三次语法错误。之后统一用 np.multiply、operator.mul、chr() 拼接绕开。
- 每个产物写完就做敏感串扫描（盘符、用户目录、网址、@、key 前缀），而不是留到最后。

## 面试式问答

问：为什么不直接用素材自带的中文字幕？
答：那 161 条是机翻，质量很差（I-05），只作为对照基线。

问：怎么证明脱敏真的生效？
答：两层。单测（Rust 与 Python 各自）；实测中 260 句译文过 for_cloud 后 0 句被改，另用 3 条合成探针（邮箱+手机号、key 样式串、本地路径）确认全部被替换。

问：空间渲染好不好，怎么量化？
答：逐句比较原声与配音的左右响度差（ILD）：相关系数 0.973，平均差 1.22 dB，左/中/右一致率 76.9%。这是客观代理，不替代人耳。

问：最大的未完成项？
答：人工听感抽查尚未做；配音链路还没接入 Operation Registry（I-03）；ASR 慢的原因未定（I-12）；edge-tts 只有 24 kHz，配音缺 11 kHz 以上高频。
